# Dynamic MERN developer portfolio

A professional portfolio with a **custom admin** you own. The public site is server-rendered from MongoDB. Adding education, affiliations, certificates, trainings, projects, or skills is a dashboard action — not an HTML edit.

## Stack

- Next.js (App Router) + TypeScript + React
- MongoDB + Mongoose
- Tailwind CSS + shadcn-style UI
- JWT httpOnly cookie auth for `/admin`
- Cloudinary uploads (local disk in development)
- Resend for the contact form
- Motion + Lenis for restrained motion
- Lucide (UI) + Simple Icons (tech logos)

## Local setup

1. Create a MongoDB Atlas cluster (or run MongoDB locally).
2. Copy env values:

```bash
copy .env.example .env.local
```

3. Set at least:

- `MONGODB_URI`
- `JWT_SECRET` (long random string)
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`

4. Install and run:

```bash
npm install
npm run dev
```

The first successful database connection seeds the admin user, profile, section registry, and sample content.

- Public site: [http://localhost:3000](http://localhost:3000)
- Admin: [http://localhost:3000/admin](http://localhost:3000/admin)

Re-seed (destroys existing content):

```bash
npm run seed -- --force
```

## What you control from /admin

- Profile (name, bio, socials, resume, SEO)
- Section order and visibility
- Experience, education, affiliations, certificates, trainings, projects, skills
- Drag-reorder, publish/hide, image/file upload

Hidden sections and unpublished items do not render on the public site.

## Cloudinary

Required on Vercel (the filesystem is read-only). In development, uploads go to `public/uploads` if Cloudinary env vars are empty.

Create a Cloudinary account, then set:

- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`

## Contact form (Resend)

Works on Vercel. Create a free account at [resend.com](https://resend.com), then set:

- `RESEND_API_KEY` (from [API Keys](https://resend.com/api-keys))
- `RESEND_FROM` — testing: `ROME <onboarding@resend.dev>` (can only send to the email on your Resend account). Production: a from-address on a [verified domain](https://resend.com/domains), e.g. `ROME <hello@yourdomain.com>`
- `CONTACT_TO_EMAIL` (inbox that receives messages; defaults to `ADMIN_EMAIL`)

Without `RESEND_API_KEY` in development, the form logs the message and still returns success. In production it returns an error until Resend is configured.

## Analytics

Pick one (optional):

- Plausible: `NEXT_PUBLIC_PLAUSIBLE_DOMAIN=yourdomain.com`
- Umami: `NEXT_PUBLIC_UMAMI_WEBSITE_ID` and `NEXT_PUBLIC_UMAMI_SRC`

## Deploy on Vercel + Atlas

1. Push this repo to GitHub.
2. Import the project in [Vercel](https://vercel.com/new).
3. Add every variable from `.env.example` in the Vercel project settings. Set `NEXT_PUBLIC_SITE_URL` to the production URL.
4. In Atlas, allow the Vercel IP ranges (or `0.0.0.0/0` for a portfolio) and use the connection string as `MONGODB_URI`.
5. Deploy. Sign in at `/admin` with `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

OG image, favicon, sitemap, and robots.txt are generated by the app. `/admin` is disallowed from indexing.
